# MeloDesk

Нативный клиент Telegram Desktop с музыкальным разделом. Версия 0.19.2, Windows x64.

Чаты, каналы и интерфейс основаны на Telegram Desktop v7.3.3. Музыкальный модуль поддерживает поиск, плеер, локальные плейлисты, любимые треки и исполнителей, импорт публичных плейлистов и первоначальные рекомендации по выбранным артистам. В настройках доступен TgWsProxy By FlowSeal. Баннер MeloDesk News встроен в эту версию и не требует рекламного сервера.

## Установка

Скачайте MeloDesk-Setup-0.19.2-x64.exe из Releases. Установщик работает для текущего пользователя. Архив MeloDesk-0.19.2-win-x64.zip содержит приложение без установки: распакуйте его целиком и запустите MeloDesk.exe. MusicHost и Proxy должны оставаться рядом с приложением. Профиль и музыкальная библиотека хранятся в данных пользователя Windows, а не внутри архива; этот вариант не переносит аккаунт между компьютерами.

## Исходники

- Native/ — полный снимок изменённого Telegram Desktop, включая закреплённые подмодули без истории Git.
- Music/ — управляемый код. В клиенте используется Music/MusicHost/MeloDesk.MusicHost.csproj. Корневой Music/MeloDesk.csproj также используется существующими регрессионными проверками.
- Proxy/ — исходники интеграции TgWsProxy и закреплённые зависимости.
- AdServer/ — необязательная локальная панель рекламы; для встроенного баннера запускать её не требуется.
- packaging/ — настройки и скрипты сборки; BUILD.md — инструкция.
- SOURCE-MANIFEST.json — контрольные суммы включённых исходников; UPSTREAM.json — версии и ревизии основы.

Сессии Telegram, личные плейлисты, локальные настройки, ключ панели рекламы и ваши Telegram API credentials в исходники не входят. При самостоятельной сборке разработчик указывает свою пару api_id/api_hash. Пользователи готового приложения входят в Telegram по номеру телефона.

## Публикация на GitHub

Содержимое этого архива разместите в репозитории. Создайте Release с тегом v0.19.2 и прикрепите установщик, архив приложения, архив исходников и SHA256SUMS.txt. Бинарные пакеты размещаются в Releases. Исходники можно добавить обычным git add .; служебные .gitignore компонентов заменены общим правилом в корне архива. Сборочные каталоги и личные конфиги исключаются этим правилом.
